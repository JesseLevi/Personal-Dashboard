App-wide decisions with no other home: iOS standalone PWA, per-page home-screen identity, safe-area handling, theme. Sidebar and drawer behaviour is in `Sidebar.md`.

## Anatomy
Root layout wraps everything in `next-themes` `ThemeProvider` + `NextIntlClientProvider`. `AppShellNav` (client) is a flex row: a flow spacer, the fixed desktop `Sidebar`, the mobile drawer, then `<main className="flex min-w-0 flex-1 flex-col gap-page-stack pt-[max(1rem,env(safe-area-inset-top))] pb-page-bottom pl-page-left md:pt-20">`. `min-w-0` is load-bearing: without it the Kanban carousel stretches `main` instead of scrolling inside its row. (#102)

## Deliberate decisions
- iOS standalone: `appleWebApp` + manifest. `statusBarStyle: "black-translucent"` is a deliberate user choice (full-bleed under the status bar, not the "default" the ticket body suggested), which is why `viewportFit: "cover"` is a hard prerequisite and every chrome element that can reach the top of the viewport must handle `env(safe-area-inset-top)`. (#172)
- Next 15.5 emits `mobile-web-app-capable` for `appleWebApp.capable`, never the iOS-specific tag older iOS needs, so `metadata.other` adds `"apple-mobile-web-app-capable": "yes"` directly. Redundant, not wrong, once Next fixes it. (#172)
- Product name "Atlas" in manifest `name` / `short_name` / `appleWebApp.title` is a literal string, not a next-intl key: a manifest is a static route with no locale, and the name is an identifier. (#172)
- Safe-area audit with `black-translucent`: `Sidebar` root `pt-[max(1rem,env())]` (permanent chrome, so padding); `SidePanel` `md:pt-[env()]` (only the `md:` shape reaches the top); `PageHeader` is `sticky top-[env(safe-area-inset-top)]`, deliberately `top` and not padding because padding would stack on `main`'s own top padding while unscrolled; `main` mobile `pt-[max(1rem,env())]`. `md:pt-20` stays a flat value on the assumption 80px clears any desktop inset. (#172, #113)
- Touch polish in `globals.css`: `overscroll-behavior: none` and transparent tap highlight on `html`; `.chrome-touch` (coarse pointers only: no touch callout, no user-select, `touch-action: manipulation`) on `Button`, `Sidebar` nav and `PageHeader`. Never on recipe text, ingredient names or notes, which must stay selectable. No blanket zoom disabling. (#172)
- Per-page "Add to Home Screen": each of Te-Doen, Recepten, Winkelmand, Notities has its own route-segment `icon.png` (favicon) and `apple-icon.png` (180 flat square) via Next's file convention, plus its own manifest Route Handler returning `MetadataRoute.Manifest` (`application/manifest+json`) linked through `metadata.manifest` on the page (Notities also on `[noteId]`). Next's `manifest.ts` convention is root-only, hence the Route Handlers. Root `app/manifest.ts` (`id: "/"`, `start_url: "/te-doen"`) is untouched. Icon and landing page must move together: a per-page apple icon with a shared `start_url` would misrepresent where the shortcut goes (the GitLab #427560 failure mode). (#223 follow-up, #390)
- Every manifest has a unique `id` + `start_url` (Safari 16.4's manifest `id` is what makes N installs on one origin independent) but `scope: "/"` everywhere: narrowing scope would pop Safari's address bar when tapping another module in the shared `Sidebar` from inside an installed page. Verified on a real iPhone 2026-08-13: three distinct icons each open their own page. (#223 follow-up)
- Glyphs: Te-Doen `Columns-3`, Notities `Notebook`, Recepten `Folder-closed`, Winkelmand `Shopping-basket`, drawn as strokes `#79716B` (`text-secondary`) on `#F5F5F4` (`surface-primary`), corner radius 32 at 180. Notities' 192/512 were rendered from lucide `notebook` (`#78706A`, 128/180 of canvas) because Figma was unreachable. (#223, #390)
- Home-screen icons are flat full-bleed squares (rx stripped): iOS applies its own mask and does not honour `maskable`, so rounded exports leave dark corners. Favicons (`icon.png`, 64) keep rounding and transparency. Manifest icons also list `purpose: "maskable"` on the same flat PNGs (glyph spans about 59% of the canvas, inside the 80% safe circle). Rasterise with Playwright/Chromium at the exact target size (`omitBackground`), not `qlmanage` (non-deterministic) and not a raster upscale. (#172, #223)
- Theme: `next-themes` with `attribute="data-theme"`, `defaultTheme="system"`, `enableSystem`; system preference only, no switch UI (not in Figma). `<html suppressHydrationWarning>` is required because its blocking inline script (first thing in `<body>`) sets `data-theme` and `color-scheme` before paint, which also keeps it ahead of the streamed skeletons. No `dark:` utilities anywhere; dark values live in `app/theme.css`. (#206)
- `viewport.themeColor` is a light/dark pair (`#F5F5F4` / `#1C1917`, `surface-primary`'s stone-100 / stone-900). Manifest `theme_color` / `background_color` stay single light `#F5F5F4`: the manifest spec has no media variant (W3C manifest #975) and they paint splash and install chrome before any theme is known. (#206)
- The Playwright visual suite stays light-only: no Figma dark frames exist to diff against and dark baselines would double the flaky set. Use Ladle's Light/Dark toggle by hand. (#206)

## Token gaps and flags
- `main`: `pl-page-left`, `gap-page-stack` (`spacing/layout/page-stack`, 24), `pb-page-bottom` (`spacing/layout/page-padding-bottom`, 80), measured on both `Main` nodes. (#205, #219)
- `pt-[max(1rem,env(safe-area-inset-top))] md:pt-20` stays raw with a `spacing-flag:`: `paddingTop` binds `spacing/layout/page-padding-top` (16 -> 80, self-switching), but `pt-page-top` would drop the safe-area `max()`, and `md:pt-page-top` double-applies the self-switch. A `max(var(--spacing-page-top), env())` form would extend safe-area handling to desktop, a product call. Undecided whether desktop `pt-` should carry the `max()`. (#219)

## Gotchas
- After deploy the user must delete the existing home-screen icon and re-add it from Safari: iOS reads the manifest and `apple-mobile-web-app-*` tags only when an icon is added.
- Nothing here has run on a real signed-in session on the dev machine (no `.env`, `middleware.ts` calls `getClaims()` unguarded); the safe-area values are unverified on a device.
- The login page's marketing PNG stays light in dark mode (an asset gap, not a token bug).
- `te-doen/manifest.webmanifest/route.ts` still points at `#per-page-home-screen-icon-unverified`, which is resolved.
