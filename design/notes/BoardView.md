## Anatomy
Not a new Figma leaf: `Carousel` (row) > `CardContainer` (column, `emptyState` for an empty column) > `Card` (per-item wrapper) > the caller's `renderItem` (a `Card-content/*` molecule). BoardView owns only drag mechanics and generic column/item plumbing; no Te-Doen or Recipe field lives here (no priority, due date, image).
- Drag stack: `@dnd-kit/react` + `@dnd-kit/helpers` (0.5.0, pre-1.0, chosen over classic `core`+`sortable` for native multi-column sorting). `@dnd-kit/dom` and `@dnd-kit/abstract` are direct dependencies because named exports are imported from them. Per card: `useSortable({id, index, group: columnId, type/accept: "item"})`. Per column body: `useDroppable({accept: "item", collisionPriority: Low})`. `DragDropProvider` + `move()` on `onDragOver` gives live reorder (dnd-kit's default optimistic sorting is the "insert placeholder" effect; Figma draws no placeholder). `onDragEnd` builds the `onMove` payload via `isSortable`/`group`/`index`; cancel (Escape) restores a `snapshot` ref.
- Only `ref` goes on the element in this dnd-kit generation (no `attributes`/`listeners`); the default `KeyboardSensor` stays untouched.
- Column width: `Carousel columnWidthClassName={BOARD_COLUMN_WIDTH}` = `w-74 md:w-80` (296 mobile, 320 desktop). Figma's "Afgerond" mobile column measures 320 (authoring anomaly, see `Carousel.md`).

## Deliberate decisions
- No drag handle: Figma draws none and the "Dragging with mouse" annotation sits on the Card itself, so the whole card is the activator. (#90)
- `onMove` reports only. `itemsByColumn` is local state purely for live drag feedback, re-derived from `columns` on every prop change except mid-drag (a prop update must not yank the card from under the pointer). Persistence is the composer's job. (#90)
- Sensor config is a function of the real per-pointerdown event, `boardCardActivationConstraints(event)` (exported, unit-tested in `tests/board-view-sensors.test.ts`): `touch` -> `Delay{750ms, tolerance 16}`; mouse/pen -> `Delay{200, tolerance 10}` + `Distance{5}`. Branching on `event.pointerType`, not a `matchMedia` read at mount, is right for hybrid devices. (#115)
- Touch hold is 750ms, not Figma's 2s ("On mobile when holding for 2s activate drag-handle", annotation on `3680:1442` is not updated). User decision after real-device testing (2s felt broken). Figma deviation, tracked as decided, not as an open design question. (#118)
- Touch `tolerance` is 16, deliberately generous: 5 on a 2000ms delay was unreachable in practice because dnd-kit aborts the pending timer permanently once the finger drifts past tolerance (about half a millimetre on a DPR-3 phone). With panning restored, the browser's own slop decides scroll vs hold and fires `pointercancel`, so tolerance only has to absorb involuntary jitter. Do not re-tighten. (#116, #118)
- Mouse needs an explicit activation constraint: dnd-kit's library default for a mouse whose target is the drag element itself is no constraint at all, so any click activated a drag and swallowed `onClick`. With 200ms/10px + 5px a plain click never activates and `onItemClick` fires; after a real drag dnd-kit suppresses the trailing click itself. (#94)
- Card wrapper on coarse pointers uses `touch-manipulation` + `select-none` + `touch-callout-none` (class in `app/globals.css`, no Tailwind utility for `-webkit-touch-callout`), `any-pointer: coarse` so hybrid devices keep it. `touch-none` was tried and broke swipe-scrolling a column; `touch-manipulation` still permits pinch-zoom. dnd-kit scroll-locks by itself once a drag activates (pointer capture + non-passive `touchmove`), so pending-phase `touch-manipulation` and active-phase lock do not conflict; confirmed on real iPhone/iPad Safari. (#116, #118)
- `dragDisabled` flips `disabled` on every `useSortable`/`useDroppable` and swaps `cursor-grab` for `cursor-default`; same DOM and provider. Set by `/te-doen` whenever a `?sort=` view is active (a drop index is meaningless against the stored `position`); reasoning in `TeDoenBoard.md`. (#95)
- `isItemMuted(item, columnId)`: the card wrapper gets `opacity-30 line-through`, evaluated against the column the item currently sits in (live, also mid-drag). `isDragging`'s `opacity-40` comes later in `cn()` and wins. Used for `/te-doen`'s last column; story `LastColumnMuted`.
- `columnMotion` (`"in" | "out"`) puts `animate-blur-in/out` plus `blurFadeStagger(columnIndex)` on each `CardContainer`, never on `Carousel` or the drag provider. The caller must unset it once the animation has played, because the `both` fill keeps a filter on the columns. Story `BoardSwitch`.
- `renderAddMenu(columnId)` is forwarded to `CardContainer.addMenu`. (#318)
- `renderColumnTop(columnId)` puts non-draggable content above a column's items, outside the sortable list and the droppable wrapper, and not counted in the header count. In an empty column it sits above the empty-state button. Used by `/recepten` for offered recipes (`SharedRecipeOffer`). (#467)

## Token gaps and flags
- Sortable-cards wrapper `gap-stack-sm`, standing in for `CardContainer`'s Content-slot gap (`spacing/stack/stack-sm`); not independently measured. (#205)

## Gotchas
- The droppable ref needs a real box: a `display: contents` wrapper has no rect, so dropping into an empty column silently failed. Non-empty wrapper is `flex flex-col gap-stack-sm` (CardContainer's own gap no longer applies one level down); empty wrapper is `flex w-full flex-1 items-center justify-center`, deliberately larger than the visible button so the whole column body is a drop target.
- `tolerance` must always be a number: `DelayConstraint` calls `exceedsDistance` unguarded, so `undefined` throws a TypeError on the first pointermove (unlike `DistanceConstraint`). The test asserts `typeof === "number"`. (#116)
- Playwright cannot drive this with `locator.dragTo()` (native HTML5 drag events, which `PointerSensor` ignores); use `page.mouse.down/move x N/up`. Keyboard: Space picks up, arrows move, Space commits.
- Drop-settle delay on `/te-doen` is not from this component: a card settles about 246ms after mouseup (dnd-kit's 250ms drop animation); a 3s hang there came from `router.refresh()` in `TeDoenBoard`, see `TeDoenBoard.md`. (#114)
- Scroll chain (hidden scrollbar, clip at sidebar, right margin) lives entirely in `Carousel.tsx`; see `Carousel.md`. (#110)
- The empty-state Figma width (312x160) is not modelled separately; an empty column uses the same `columnWidthClassName` wrapper. See `CardContainer.md`.
