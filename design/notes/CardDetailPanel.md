## Anatomy
Page-level composition of `SidePanel` + `InputField` / `Dropdown` / `Tag` / `Button` as Figma nests them, one component for create and edit (`target.mode`). Not an atomic-design leaf, so not in `design/figma-map.json`. It lives in `app/(app)/te-doen/` because it renders one concrete card shape (`cards.title/description/priority/size/due_at/column_id`), same precedent as `TeDoenBoard.tsx`.

## Deliberate decisions
- Labels (ADR-0052, #716): `CardLabels.tsx`, a section of this panel after "Deadline", composed of `Dropdown`, `Button`, `Tag` and `InputField` (no new component). The panel holds `labels: string[]` and sends it as `labels` with create and update, so Save and the server are unchanged. A name is a label's identity (case ignored), because a new label has no id yet.
  - Trigger: a `Dropdown` (`Button presentational`, "Kies labels") that stays open while labels are toggled; `labelsEpoch` remounts it on every reset so it opens closed with an empty filter. `boardLabels` (`boardLabels(board.columns)`) is a prop; the options are those plus the card's own, alphabetical (`labelOptions`).
  - List: an `InputField` filter on top (`maxLength` = `LABEL_MAX_LENGTH`), then one `Button` per option (`white`, `filled` + `Check` + `aria-pressed` when selected; a tap toggles), then the outline `Plus` "Nieuw label" row, outside the scrolling option list (`max-h-60`) so it stays reachable. With filter text the row reads `Nieuw label "{text}"` and adds it through `addLabels` (the `parseLabelInput` rules, the board's spelling if it exists, at most `LABELS_PER_CARD`, `LABEL_MAX_LENGTH`); without text it focuses the filter. It is hidden when the text equals an existing label.
  - Enter in the filter (`resolveFilterEnter`): the exact match, else the only match, else create; empty text does nothing. Picking selects (it never deselects, so a second Enter is harmless), clears the filter and keeps focus there for the next label. A refused add shows `labels.limitHint` / `labels.tooLongHint` in a `role="status"` line.
  - Keyboard: ArrowDown on the open trigger enters the list; arrows walk filter, options and the "Nieuw label" row (stopping at the ends; ArrowUp on the filter returns to the trigger); Escape is `Dropdown`'s own (closes, focus back on the trigger, the panel stays open). Opening scrolls the list into view (`scrollIntoView({ block: "nearest" })`), and focusing the filter scrolls it above the on-screen keyboard natively.
  - Chips (the card's labels, selection order) sit under the field: each is a `button` around a neutral `Tag` with the `Tag` icon and a trailing `X`, a 40 px tap target, `aria-label` "Label {name} verwijderen". They cannot live in the trigger because `Dropdown`'s first child must be inert.
  - A very long name (~40 characters) wraps to two lines inside its 40 px "Nieuw label" row; accepted.
- Mutations (`onCreateCard` / `onUpdateCard` / `onMoveCard` / `onDeleteCard`) and `onMutated` are props. Only `TeDoenBoard.tsx` imports the `"use server"` actions and `useRouter()` (`onMutated={() => router.refresh()}`); this file imports neither `next/navigation` nor the actions module. A direct `useRouter()` threw "expected app router to be mounted" under Ladle's plain Vite runtime, and this is what lets the stories mock every action. (#94)
- Status/Prioriteit/Grootte use `Dropdown` directly, not `InputField`'s `button` slot: nesting two atoms that each draw `rounded-xl border` doubled the chrome, while Figma has one bordered container per field. `Dropdown`'s own `label` already reproduces the field title and its click-to-toggle is the annotated behaviour. (#94)
- Selected-item-first: the current value is the Dropdown's first child and this file reorders on every render. A `key` on each Dropdown (column id / priority / `size ?? "none"`) remounts it on selection, which is the only way to collapse it (`Dropdown` has no external open control). (#94)
- Prioriteit/Grootte options are a plain `<button>` around a `Tag` (Tag is an inert `<span>`); the selected one is a `Tag` inside `Dropdown`'s own trigger button, which spans label, Tag and chevron. Trigger and options share `TAG_ROW` (`flex h-10 items-center px-component-sm`, the metrics of a `Button` row), so each option is a 40 px tap target and the selected Tag lines up with the options. The field height itself comes from `Dropdown`'s `min-h-10` trigger. (#604) Option hover is `hover:bg-surface-highlight-white-selected`: Figma's Dropdown option rows (node `3705:4446`) are `Button/Default` instances on the white ramp, and White's Hover state reads the `-selected` token. It was `surface-hover`, retired as an orphan (#204), then `-hover` (#204), corrected here. (#213)
- Grootte is nullable (`cards.size`, "a card need not have a size"). Unset renders a neutral Tag with `fields.sizePlaceholder` ("Geen grootte" / "No size") rather than a fifth enum value; Figma's sampled "XS" is stale placeholder text, the real values are `s/m/l/xl` per the DB CHECK. The option list is `[null, ...SIZES]` minus the current value so a set size can be cleared again; React keys use `value ?? "none"`. (#94, fixed 2026-08-04)
- Deadline (Figma's "Datum") is plain text per Figma's annotation ("For now date will be only text based"; no datepicker, no `type="date"`). The raw text (dd-mm-yyyy or dd/mm/yyyy) goes to the server unparsed: `lib/boards/schemas.ts`'s `dueAt` accepts ISO or free text and parses via `lib/boards/dates.ts#parseDueAtText` in a Zod `.transform()`, so parsing happens in the server action. Empty text is sent as explicit `null` to clear; the schema rejects `""` on purpose. (#94)
- A Status change on save goes through the existing `moveCard` with `targetIndex: Number.MAX_SAFE_INTEGER` after `updateCard`, not through `updateCard`: `updateCardSchema` has no `columnId` because a column change needs a new fractional `position` (`lib/boards/positioning.ts`). `moveCard` clamps the index server-side to "append at end". (#94)
- Two-step delete: "Verwijderen" swaps the same SidePanel footer to a confirm state (full-width prompt line, then Annuleren + destructive Ja/verwijderen); no `window.confirm`, no dialog. Uses the shared `DeleteConfirm layout="stacked"` + `useDeleteConfirm`. User decision 2026-07-24; no Figma node models it.
- Reset during render, never remount. A `targetKey` (`edit-${id}` / `create-${columnId}`) is compared against `prevTargetKey` / `prevOpen` held in state, and fields, `deleteConfirming` and `error` are reset synchronously when `open && (!prevOpen || targetKey changed)`. Rejected: a JSX `key` on the panel. Remounting `SidePanel` created a fresh dialog node already in the open position (no closed frame to transition from, so no animation on every never-before-mounted target), while a non-varying key leaked the previous draft when "create" was opened twice in the same column. Rejected: a `useEffect` reset, which paints one stale frame first. Keying on `open` would have made the animation bug worse. (#103, #105)
- Footer: normal state is a `flex gap-inline-sm` row whose buttons carry `grow basis-0` (never `flex-1`, see `SidePanel.md`); `BoardPanel` follows the same convention. (#103)

- **Deadline and Gepland op** (#714, ADR-0037): two fields because two facts. Gepland op comes first and is always shown. Deadline shows when the card has a `due_at`; otherwise an outline `Button` ("Deadline toevoegen") sits in its place and reveals the field with focus. `deadlineShown` is state reset with the other fields on open, so clearing the text keeps the field while editing and hides it on the next open. Only a field the user asked for (empty text) takes focus.

- **Gepland op** (#488) is the day the user intends to do the card (`cards.planned_for`, a date), distinct from the deadline `due_at` (a moment). It has the deadline's input style and text format (dd-mm-yyyy), is sent as `plannedFor` (empty text is `null`, which clears it) and shows in the Agenda as a planned item. It is displayed in UTC because a date has no zone. Invalid text is refused by `plannedFor` in `lib/boards/schemas.ts`.

- **Subtaken** (ADR-0053, #694) live in `CardSubtasks.tsx`, a section of this panel; the six subtask actions are props like the card ones.
  - Writes are immediate and not tied to Save. They are optimistic and revert with the panel's error line on failure; every write calls `onMutated`, so the board's "3/7" chip follows.
  - Create mode buffers titles in `draftSubtasks`. `handleSave` writes them with one `addSubtasks` call after `createCard`. `createdCardId` makes a retry after a failed subtask write skip the second `createCard`. Buffered rows cannot be checked or promoted.
  - Row: `Checkbox` labelled by the title (an `::after` widens its 32 px to a 40 px target), a title button that turns into an `InputField` (Enter or blur saves, Escape cancels without closing the panel, empty or unchanged = no write), and a `variant="transparent"` icon `Button` opening a menu built like `AgendaMoreMenu` (`Dropdown role="menu"`, `usePopoverPosition` in the panel's scroll area): "Maak er een kaart van" (`promoteSubtask`, then `onMutated`; the panel stays on the parent) and "Verwijderen".
  - Order: open rows by position, then done rows behind the "{n} afgerond" toggle (`aria-expanded`, collapsed while any row is open). There is no manual reorder in v1.
  - Add row: Enter adds and keeps focus; pasting several lines adds one subtask per line, in one call (`lib/boards/subtasks.ts`). Titles are cut at 200 characters and the list at 50, where the field is disabled with a hint.
  - "Alles af. Naar {kolom}?" shows while the card has subtasks, none is open, the board has a done column (`CardDetailPanelColumn.isDone`, the first by position) and the card's saved column is not one. Its button calls `onMoveCard` (append at end). Nothing moves on its own, and a card moved into a done column checks nothing.

## Token gaps and flags
- Footer row `gap-2` -> `gap-inline-sm`: the "Bottom" node (`3779:4858` mobile / `3779:4950` desktop) is HORIZONTAL with `itemSpacing` 8 bound to `spacing/inline/gap-sm`, identical on both breakpoints. (#219)
- Two `rounded-lg` click wrappers per field around the Priority/Size option Tags (option rows only; the selected Tag's row has no hover) stay raw with `spacing-flag:`. They are a code-only click affordance with no Figma node; the Dropdown's expanded state in Figma (`Te doen/Mobile/SortOnClick` `3877:6683`, Slot `3878:13062`) draws `Button/Default` instances instead. `Tag`'s own `rounded-lg` is `radius/control` (node `3626:4515`, `Tag.md`), but that is Tag's binding, not this wrapper's, so it is not converted by inference. Revisit if Figma gains a node for this trigger. (#219)
- `InputField`'s "hide the input row, show only the button slot" gap (`InputField.md`) is not solved here: these three fields are built on `Dropdown` instead.

## Gotchas
- `LabelsOpen` and `LabelsOpenFiltered` click the Labels trigger and set the filter value on mount, because `Dropdown` has no open prop; the closed ones are `LabelsNone` and `LabelsSelected`.
- Stories (`CreateItem`, `EditItem`, `EditItemNoDeadline`, `EditItemDeleteConfirm`, `Interactive`) must wrap the panel in `<div className="min-h-screen">`: `SidePanel` is `position: fixed` and the visual runner collapses `#ladle-root > div`, so without it baselines were 1280x64 slivers that covered nothing (a chevron removal passed the old baselines; with the fix it fails at 54px). (#106)
- `EditItemDeleteConfirm` clicks the real "Verwijderen" button on mount (found via the `nl` catalog's `deleteLabel`) because the confirm state is local and has no prop; do not add a test-only prop. (#106)
- Real `createCard` / `updateCard` / `moveCard` / `deleteCard` round trips, RLS and the full `/te-doen` render cannot run on the dev machine (no Docker/Supabase); CI covers them.
