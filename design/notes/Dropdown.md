## TICKET #108 (2026-07-27/28) — square corners fixed, chevron moved out of the trigger

**1. Square-cornered outer container — confirmed then fixed.** Measured in a real browser (Playwright, `dropdown--closed` story) before touching anything: outer wrapper (`flex w-full flex-col gap-2`) computed `border-radius: 0px`; inner panel (`rounded-xl border border-border bg-surface p-1`) computed `12px`. `TeDoenHeader.tsx`'s `<Dropdown className="shadow-sm">` (both board-switcher and sort menus) merges onto the outer wrapper per the documented `className` contract, so the shadow painted a square box behind the rounded panel — exactly the diagnosis, not a different bug. Fixed with the minimal option: `rounded-xl` added to the outer wrapper unconditionally. In labelless mode the wrapper's box is pixel-identical to the panel's (single child, no padding) — measured post-fix, both report `12px`, exact. In labelled mode the corners now land on the label+panel group as a whole, which is currently invisible (no caller themes that box today) — a real, documented behaviour change (not silently absorbed), flagged here rather than left implicit. `className` contract itself (merges onto the outer wrapper) is unchanged — no caller edits needed for this fix.

**2. Chevron moved from the trigger into Dropdown's own trigger row.** Re-fetched the side-panel desktop node (`3779:4938`, "Te doen/Desktop/AddItem" — same node this file's node-id already claims via SidePanel's pair) rather than guessing. For Status/Prioriteit/Grootte, Figma models each field as an `Input-field` instance (`Button: true`, `Trekking-icon: true`, `Text: false`) — **not** a bare stretched/transparent trigger:

- `Container` (the bordered `rounded-xl` box, `fills: white/#FFFFFF` or `border: #D6D3D1`=`border` token, `padding: 4px`, `gap: 12px`, `sizing: horizontal fill`) holds two children: `Content` (`sizing: horizontal fill, vertical hug`) and `Trekking-icon-container` (`padding: 8px 8px 8px 0`, hug).
- `Content` wraps the `Slot` — the actual `Button/Default` instance (Status: `Style=Filled`, hug-width, unchanged pill) or `Tag` (Prioriteit/Grootte) — which stays **hug**-sized and left-packed even though its ancestor `Content`/`Container` fill the row.

So Figma's own answer to "kan dit met dit component?" is a **third shape**, not either of the two options weighed going in: the chevron sits in its own fixed trailing column, *outside* the pill's fill (ruling out `align="left"` + `trailingIcon` inside a stretched transparent trigger — Figma's pill stays filled and hug, never stretched/transparent), and the pill itself stays a real, unduplicated `Button`/`Tag`-button (ruling out re-implementing the pill as a non-interactive lookalike). Reproduced with `<div className="min-w-0 flex-1">{trigger}</div>` + a `Dropdown`-rendered `<Icon name="ChevronDown">` sibling, `gap-3` between them (Figma's `Container` `gap: 12px`) and `mr-2` on the icon (Figma's `Trekking-icon-container` `pr-2`, `py-2` reproduced for free by the row's own `items-center` against a 40px-tall trigger) — measured post-fix: chevron's right edge sits 13px from the panel's own right edge (`border` 1px + panel `p-1` 4px + `mr-2` 8px = 13, matching the box model exactly, not approximately).

**API change, not a classname tweak, and deliberately documented as one.** `CHEVRON_ROTATE` (the old `aria-expanded:[&>svg]:rotate-180` sibling-selector trick targeting a direct-child svg of the *trigger*) is removed entirely — the chevron is no longer a child of the trigger at all, so that selector could never have reached it. Rotation is now driven directly off Dropdown's own `isOpen` state via a plain conditional class on the `Icon` Dropdown itself renders. This is simpler and more robust than the selector it replaces (no dependency on the trigger's own DOM shape), and it retires the duplication `#108`'s own ticket text flagged: Status/Prioriteit/Grootte previously each hand-rolled their own trailing-chevron markup (`Button`'s `trailingIcon` prop for Status, a manual `<Icon>` for the other two); now none of them render a chevron themselves — `CardDetailPanel.tsx`'s three triggers were all updated to stop doing so (Status: dropped `trailingIcon="ChevronDown"`; Prioriteit/Grootte: dropped the manual `<Icon>` and the `gap-2` that spaced it, since the trigger `<button>` now wraps only its `Tag`).

**"Whole row clickable" — deliberately NOT built, flagged rather than silently dropped.** `#108`'s text asks that the entire row (pill + chevron) open/close, not just the pill. Figma gives no signal either way (it's a static mockup); building it would mean either an invalid `<button>`-in-`<button>` (Status already uses a real `Button`) or wrapping a real interactive trigger in a second, non-`<button>` interactive element (`role="button"` div), which is a documented ARIA/keyboard-focus anti-pattern (ambiguous tab order, two focusable controls doing the same thing). The chevron is Figma's own separate, non-interactive sibling — same relationship `InputField`'s trailing icon already has to its content column (the Datum field's Calendar/Pencil icons aren't independently clickable either) — so it stays a decorative, `aria-hidden` icon; the click surface is unchanged (the pill only, already a full 40px-tall target). This is this codebase's own call, not Figma's; flagged here per `CLAUDE.md`'s "you are not the architecture layer" rule rather than silently building only half the request.

**Hugging vs. filling — corrected, not contradicted.** `#100`'s "Figma's closed-state slot is horizontal: hug" is still true at the innermost level (the `Slot`/`Button` itself never stretches) but was incomplete about the ancestor chain: `Container`/`Content` both `sizing.horizontal: fill`. The panel's `items-start` (which `#100` added specifically to keep the *whole* trigger hugging) is now dropped — the new trigger row supplies its own `w-full`, and the `Slot`/`Button` inside still hugs by ordinary block-child sizing, so no contradiction with the corrected reading. `design/notes/Dropdown.md`'s own #100 entry is left as-is below (superseded, not deleted, per this file's own convention).

## UPDATED for ticket #100 (2026-07-25) — trailing chevron, trigger moves to the active item, hugging selection

Re-fetched both nodes the ticket named: `3779:4939` ("Pull-up panel", desktop AddItem — closed-state reference) and `3877:7682` (sort Dropdown instance — open-state reference). `3877:7682`'s own `Slot` confirms the open-state option rows are Figma `alignSelf: stretch, horizontal: fill` (each `Button/Default` instance stretched to the panel width) — unchanged, still what `restChildren` renders. The closed-state hug comes from `3779:4939`'s Input-field "Slot" (`sizing: hug/hug` around its Button instance) — Dropdown's own node still samples no distinct closed state (unchanged since #61), so this remains this atom's own interpretation, now Figma-corroborated via the sibling Input-field node rather than only the ticket's reference screenshot.

**Trigger API — caller supplies the trigger, Dropdown does not wrap it.** The alternative considered and rejected: Dropdown wraps the first child in its own `<button>`. Rejected because the first child is already a real interactive element at every call site — a `Button` atom (Status field, sort/board-switcher options) or a caller's own `<button>` wrapping a `Tag` (Prioriteit/Grootte) — and a `<button>` nested inside a `<button>` is invalid HTML. Instead, when `label` is present, Dropdown `cloneElement`s the first child (`Children.toArray(children)[0]`) and injects `id` (`${id}-trigger`), `aria-expanded`, `aria-controls`, an `onClick` that composes any caller-supplied `onClick` with the open/close toggle, and a merged `className` carrying the chevron-rotation rule. This makes "the first child is both the current selection and the trigger" an explicit contract of the `children` prop (documented in the component's own header comment) rather than an implementation detail — every call site's first child must be a real button-rendering element.

**Title is now inert.** `label` renders as a plain `<span id={id}>` (`text-base font-semibold text-text-muted`, matching `InputField`'s own label styling) instead of the old `<button>` trigger. The collapsible panel gets `aria-labelledby={id}` pointing at that span, so the panel's accessible name still resolves to the title even though the title itself is no longer focusable. Escape-to-close-and-refocus now targets the trigger via `document.getElementById(`${id}-trigger`)` instead of a `useRef` on the (now removed) trigger button — the trigger is caller-supplied JSX Dropdown doesn't hold a ref to.

**Chevron rotation** is a single shared class string (`CHEVRON_ROTATE`) merged onto the cloned trigger: `aria-expanded:[&>svg]:rotate-180` plus `[&>svg]:transition-transform [&>svg]:duration-[var(--duration-base)] [&>svg]:ease-base motion-reduce:[&>svg]:transition-none`. Targeting `[&>svg]` (direct-child svg only, not the leading icon nested one level deeper inside `Button`'s "Leading + Text" span) means this works unmodified for both a `Button` with `trailingIcon="ChevronDown"` (the trailing icon renders as a direct child of `Button`'s root, per #99's structure) and a caller's own `<button>` with a manually rendered `<Icon name="ChevronDown">` as its last child (Prioriteit/Grootte). Reuses the existing `--duration-base`/`--ease-base` tokens (`design/tokens.json`, already consumed by `Sidebar.tsx`'s width transition), same precedent as this file's own grid-template-rows transition. Measured in a real browser (Playwright against `pnpm ladle`): `aria-expanded="true"` gives the trailing svg a computed `rotate: 180deg` with `transition-duration: 0.2s` (== `--duration-base`); closed gives `rotate: none`.

**Hugging vs. filling** — the panel (`flex flex-col`, default `align-items: stretch`) previously stretched every child, including the first/selected one. Fixed with `items-start` on the panel, applied only when `label` is present (labelless mode still wants every direct child — there is no trigger/rest split there — to fill, so it keeps plain `flex-col` default stretch). Because `items-start` would also un-stretch the collapsible sub-list wrapper, that wrapper gets an explicit `self-stretch` so the open option rows (which fill via their own parent's default stretch, one level deeper) still get a full-width ancestor to fill against. Measured (Playwright, `Dropdown--Closed` story): trigger 142px wide inside a 338px panel (hugs); same story after opening: option rows 328px (panel 338 − 2×4px padding − 2×1px border). Measured in `CardDetailPanel--EditItem`: Status trigger 119px / Prioriteit 138px / Grootte 70px, all inside a 370px panel; open option rows 358px (370 − 8 − 2, hugging vs. filling both confirmed).

**Flagged gap narrowed, not resolved.** The labelless mode (no `label` prop — `TeDoenHeader`'s sort/board-switcher panels) still has no trigger of its own and stays a static `role="group"`; this ticket only builds the trigger/chevron/hug behaviour for the labelled case, since the labelless Figma sample (`3877:7682` itself, `Title: false`) still shows no header to turn into one. `TeDoenHeader.tsx` supplies its own open/close `Button` outside the `Dropdown`, unchanged by this ticket.

**Not verified end-to-end**: `TeDoenHeader.tsx`'s sort/board-switcher `Dropdown` usages (labelless, structurally unchanged by this ticket) could not be exercised live — `TeDoenHeader` calls `useRouter()` directly (by design, see its own header comment), which throws `invariant expected app router to be mounted` under Ladle's plain Vite runtime (confirmed by probing a throwaway story: same failure `CardDetailPanel.md` already documented for a bare `useRouter()` call), and the real `/te-doen` page needs a live Supabase session this dev machine doesn't have (no Docker). The labelled trigger/chevron/hug mechanics above were verified via the `Dropdown` stories and `CardDetailPanel`'s Status/Prioriteit/Grootte fields instead, which exercise the exact same `Dropdown` code path.

## Implementation details not covered above

- **`gap-1` is applied only in the labelless mode**, where every child is a direct flex item. With a label, the collapsible sub-list supplies its own `pt-1` instead — a parent `gap-1` would survive the `0fr` grid-row collapse (a flex gap is drawn between items regardless of their height), so a closed Dropdown would show 4px of dead space below the selected option (an asymmetric inset against the panel's 4px padding), and an open one would show 8px above the second option but only 4px between the rest. This is a ticket #61 follow-up finding.
- **`inert` (not just `aria-hidden`) on the collapsed sub-list.** `aria-hidden` alone hides content from assistive tech but does not remove focusable descendants from the tab order, so the collapsed options would still be Tab-reachable without `inert`. The first/selected child sits outside this wrapper and is never hidden or made inert.
- **Why the `label`+`id` contract stayed identical to InputField's** even though this atom is now a Client Component and could in principle call `useId()`: one consistent way to label a slotted atom across the design system was preferred over two different idioms.
