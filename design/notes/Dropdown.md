## UPDATED for ticket #43 (2026-07-20)

(1) option-content centring was actually a Button.tsx bug, fixed there (see Atom/Button note), not in this file. (2) Added real open/close disclosure behaviour — this atom is now a Client Component (`"use client"`) that owns its own `isOpen` state, a deliberate exception to the Server-Component default (justified in the component's own doc comment): the disclosure behaviour is intrinsic and identical for every caller, unlike InputField's caller-varying `button` slot, which stayed a Server Component. When `label` is present it is now a real `<button>` trigger with `aria-expanded`/`aria-controls`, replacing the old `role="group"` + `aria-labelledby` panel (dropped per the ticket: no ARIA role is needed on a disclosure's content region once the trigger carries aria-expanded/aria-controls). Enter/Space work for free (native `<button>`); Escape closes and refocuses the trigger. Animation is the CSS-grid `0fr`/`1fr` row trick (Tailwind utility classes only), respecting `prefers-reduced-motion` via `motion-reduce:transition-none`.

## FLAGGED GAPS (not built, by design)

no chevron/indicator icon was added — the fetched node samples no such affordance and one isn't invented; a labelless Dropdown (no `label` prop) has no header to turn into a trigger, so it keeps the old static always-open `role="group"` behaviour unchanged — a labelless real disclosure would need a Figma-side header/trigger added to the node (or a future dedicated trigger slot) before it can be built.

## FIXED for ticket #61 (2026-07-20)

re-fetched node 3705:4446 — still a single COMPONENT with only `Field`/`Title` propertyDefinitions, so Figma models no distinct 'closed' state at all; the one static frame it returns is the fully-open composition (three Button/Default instances, first Filled/selected, two White), same as before. Given Figma has nothing to say about a collapsed state one way or the other, the closed-state fix follows the ticket's reference screenshot rather than inventing something new: previously closing collapsed the *entire* bordered panel (border included) to zero height, leaving only the label visible, which is not a usable collapsed-select affordance. Now the bordered panel always renders and its first child (the current selection, per the fetched node's own ordering) always stays visible; only the remaining children collapse via the same CSS-grid `0fr`/`1fr` trick, now scoped to a sub-wrapper instead of the whole panel. `aria-controls` on the trigger now points at that narrower sub-wrapper's id (the actual element being hidden/shown) rather than the whole panel. No other behaviour changed: label trigger, aria-expanded, Escape-to-close-and-refocus, motion-reduce, and the labelless always-open gap are all unchanged. Stories cut from 5 exports (Plain, WithLabel, FigmaDefault, ClosedByDefault, AllVariants) to 3 (Closed, Open, Animated) per the ticket — Plain/WithLabel (no full option list) and AllVariants (redundant with the other two) added no coverage the remaining three don't already give; the labelless mode still has no story, per the ticket's note that it's a flagged Figma gap, not something to demonstrate.
