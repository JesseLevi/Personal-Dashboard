# IngredientSearchPanel
Figma: `Add recipi/ingredientList/Mobile` · node `3957:10309`, panel `3957:10337` (in `figma-map.json`); desktop panel `3957:11006` (its frame `3957:10595` returns the whole canvas, which also holds an unrelated bigger recipe-edit panel `3957:10596`/`3957:10621`; `3957:11006` is the one matching the mobile panel) · Code: `components/organisms/IngredientSearchPanel.tsx` (+ `.stories.tsx`)

## Anatomy
`SidePanel` supplies all chrome; this file supplies children and footer. Children: `InputField` "Zoeken" (trailing `Search`), then a `Card` of `CardContentIngredient` rows (name only, `checked`, `divider` between rows). Footer: one filled "Opslaan" `Button` (`Save`). A prompt line, "searching" line and error line sit between field and list. `level` forwards to `SidePanel` (`RecipePanel` passes `2`).

## Deliberate decisions
- Named for its function: the Figma layer name has no atomic-design translation. It gets a `figma-map.json` entry (unlike `CardDetailPanel`/`BoardPanel`, page-level compositions) because its content is the Figma component being built. Lives in `components/organisms/`. (#131)
- Name only, no quantity Tag on the rows (`componentProperties: {"Tag": false}` on every fetched row), and a bottom-only `#E7E5E4` divider per row; these produced `CardContentIngredient`'s optional `quantity` and `divider` props. The code draws the divider on all rows except the last. (#131)
- Props in, callback out, no `"use server"` import (ADR-0011 §2), so the panel stays Ladle-testable without a Next.js request context. `onSearch` is the thin `searchIngredients` wrapper (`app/(app)/recepten/actions.ts`) around `searchIngredientLibrary`; `queries.ts`'s `server-only` guard is import-time only, so a Client Component cannot call it directly. (#131)
- Materialisation is deferred to "Opslaan": unchecking a pick before saving costs nothing and only saved picks write to `public.ingredients` (ADR-0011 §2/§5; never a `reference` row from the UI). Library picks call `onCreateOwnIngredient` sequentially, stopping at the first failure (clear error, small selection counts). `onSave(ingredients, plainNames)` fires once with both, so callers handle a mixed selection in one call with no racing writes (`WinkelmandList`); never fired on plain close/cancel. (#131, #324)
- Selection is an internal `Map` keyed by `ingredientSearchResultKey` (`"<own|reference>:<id>"`, exported) or `"plain:<lowercased trimmed name>"`. Keying by id, not by current results, lets selections accumulate across searches. Everything (query, results, selections, errors) resets on every close, not on open. (#131)
- Zero-results row "use as plain name" is a deliberate Figma deviation (the node draws no zero-result affordance; user decision 2026-07-30; it was "add as new ingredient" until ADR-0020 §5). Built from bare atoms (`Icon Plus` + text + `Checkbox`), not `CardContentIngredient`. The `Checkbox` is the row's only interactive element, deliberately not wrapped in a `<button>` (a button around a Checkbox would nest interactive controls). A plain name creates no `public.ingredients` row: `RecipePanel` sets the line's `name` with `ingredientId: null`, the shopping list adds the name only; nutrition already leaves unlinked lines out of totals. (#324)
- `initialQuery` and `initialSelectedIds` are real props (a caller reopening with state in hand) and also what makes the Ladle baselines deterministic, since the visual harness scripts no interaction. `initialSelectedIds` applies once against the first satisfying result set, guarded by a ref that resets on close. (#131)
- Search uses escaped `ilike` substring matching, not the `pg_trgm` the ticket asked for: no migration enables the extension or indexes the ingredient name columns (see the header of `searchIngredientLibrary`). Flagged, not this component's to fix. (#131)
- `resultDisplayName`: `own` rows show the user's free-text name untranslated; `reference` rows show `name_en` for locale en, falling back to `name_nl` when empty. Exported and reused by the admin panels.

## Token gaps and flags
- Zero-results row has no fetched node. Its `gap-inline-xl rounded-container pl/pr/py-component-md` are borrowed from `CardContentIngredient`'s measured default row to sit consistently among sibling rows, not independently measured. (#205)
- Left raw, each with its own `spacing-flag:` directly above the line (the gate reads only the adjacent comment): the no-results message `px-3 pb-2` and the inner icon+label `gap-2`; both belong to the synthetic row and map to no measured binding. (#205, #218)
- Footer `gap-inline-sm` (`spacing/inline/gap-sm`), same "Bottom" pattern as `StepIngredientPanel`/`RecipePanel`. (#205)
- The 300 ms search debounce has no design or product source (same class as `SidePanel`'s drag thresholds); not escalated, easy to retune.

## Gotchas
- `onSearch` and `onCreateOwnIngredient` are in the debounce effect's dependency array. Pass stable references (the imported server action or a `useCallback`); a fresh inline closure per render re-triggers the debounce. `t` is deliberately excluded from the deps (unstable identity).
- A `cancelled` flag guards against an out-of-order response overwriting a newer one.
- Stories: `Empty`, `FilledResults` (`initialQuery="e"`), `ZeroResultsWithPlainName` (`initialQuery="Kaneel"`), `SomeRowsChecked`. Mock actions never import the real action module.
