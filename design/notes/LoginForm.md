- StepAnimation (`3934:32745`): two panes (email, password) in one `grid w-[312px]` cell (`col-start-1 row-start-1`), each a pure slide with no fade. The window never resizes.
- Step 1: `InputField` (E-mail, 312x48) + 16px + filled `Button` "Doorgaan" (312x40). The Calendar icon on the input and the icons on the button are `visible: false` in Figma, so none are built. `ErrorLine` sits between.

## Deliberate decisions
- Panes slide with `transition-[translate]`, `--duration-base`, `ease-base`, `motion-reduce:transition-none`. Active `translate-x-0`; inactive email `-translate-x-[357px]`, inactive password `translate-x-[357px]` (357 = 312 pane + 45 gap, from Figma), both `pointer-events-none` + `inert` + `aria-hidden`. Tailwind v4 `translate-x-*` sets the `translate` property, so an arbitrary transition list must name `translate`, not `transform`. This replaced a translated flex rail inside `overflow-hidden`, where `focus()` on the offscreen password input scrolled the clip window (double shift) and the hard clip cut focus rings (#396).
- Edge softening is a horizontal `mask-image` gradient on a wrapper with `p-component-lg` padding offset by negative margin and reduced `mt`: layout unchanged, focus rings stay whole. Focus moves to the newly active pane with `preventScroll`, skipped on first render (#396).
- Step 1 validates format only, client-side (`magicLinkSchema`); it never checks whether the address exists, so a valid format always proceeds to step 3 and the login flow is not an enumeration oracle. The greeting lookup is the one deliberate exception (below) (#158, ADR-0031).
- Error states deviate from the Figma `Error` frame. That frame puts the credentials error ("E-mailadres of wachtwoord klopt niet.") on an E-mail field + Doorgaan pane, a mockup artifact. Built as two real states on the correct panes: step 1 `auth.errors.invalid-email-format` (client-side), step 3 `auth.errors.invalid-credentials` (keeps the trailing period; the redrawn `3991:13224` omits it, not reconciled). `ErrorLine` collapses via `grid-rows-[0fr]`->`[1fr]` with the 16px gap on the line's own margin (never the column gap), so a collapsed line adds zero space and the button slides smoothly (#158).
- Terug and Inloggen are two `flex-1` halves, although Figma draws 153/151px (hug/rounding artifact on a 312px row with 8px gap). Escape on the password pane also triggers `handleStepBack`; kept after the Terug button was drawn since it costs nothing (#158).
- Heading uses `text-text-primary`, not Figma's literal `#000000` (#158).
- Greeting heading animation (user-designed): the name part is an inline grid going `grid-cols-[0fr]`->`[1fr]` plus opacity, child `overflow-hidden whitespace-pre`, so the centred row pushes "Hey" and the tail apart. The visual row is `aria-hidden`; an `sr-only` sentence is the h1's accessible name, so a collapsed name never leaks. The name is `min-w-0` with ellipsis; the row is capped by its column (370px at 402px), not 312px, because the sentence is about 300px (#407).
- Lookup flow: on a valid Doorgaan the lookup runs beside the step slide and never delays it. Turnstile token (`useTurnstile`, invisible, `action: login_greeting`, ~5s timeout, reset after each token) then `lookupGreetingName`. Same e-mail after Terug keeps the name without re-query; a different one collapses the old name first (250ms wait), then looks up. Stale responses (older sequence) are dropped; `null` or a throw keeps the plain greeting, no error UI. No site key means no script and a `null` token. Rate limiting, fail-closed and uniform timing live in the backend: `docs/decisions/0031-login-greeting-name-lookup.md` (#407).
- Page layout: breakpoint is `lg` (1024px), not `md`: at 820px the row layout squeezed the image into a corner. Figma only draws 402 and 1440, so the switch is this codebase's call (#158).
- The image is height-driven (`h-full`, `aspect-square`) and the login column absorbs leftover width. A width-driven square only matched Figma at 1440x868 by coincidence; at 1280x800 it left a gap (#158).
- The root `main` is `h-screen`, not `min-h-screen`: a percentage `h-full` only resolves against a definite ancestor height, and with `min-h-screen` the image measured 0x0 (#158).
- Visual pane: two static PNGs in `public/login/` (Figma URLs expire), swapped with `lg:hidden` / `hidden lg:block` because `next/image` has no art direction. `alt=""` + `aria-hidden`; `bg-surface-secondary` under it avoids a mismatched flash (#158).
- `lg:gap-page-stack` is a stack-family token on a row axis because that is how Figma binds `LogIn/Desktop`'s `itemSpacing`; use it as measured, do not "correct" it to an `inline/*` token (#219).

## Gotchas
- Ladle baselines cover `LoginForm` only, never `page.tsx`'s layout; both page-layout bugs above were only visible in a real browser at 1440x868, 1280x800, 820x1180 and 402x820. Re-check `/login` at those sizes after layout edits.
- `initialStep`, `initialState` and `initialGreetingName` are Ladle-only props that make the Figma frames story-able; a real visit always starts at the email step.
- Step-02 (`4221:14891`) draws no Terug button; the built step-3 pane keeps the Terug/Inloggen row (buttons were out of scope for #407).
- A truncated long name shows an ellipsis, then a space before the comma (cosmetic, accepted).
