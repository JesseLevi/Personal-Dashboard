# NoteTableHandles (#387, Claude-designed on request)

Row and column reordering for notes tables, plus a placement fix for the
"Table" button. Built from existing components and semantic tokens; no Figma
step. Table menu background: `design/notes/NoteEditor.md` (#330).

## Move commands (`lib/notes/table-commands.ts`)

- `moveRowUp/Down`, `moveColumnLeft/Right` are in `TABLE_COMMANDS`, so they
  show in `TableMenu` and the mobile table-actions bar without more wiring.
  Icons `ArrowUp/ArrowDown/ArrowLeft/ArrowRight` (`ArrowUp`, `ArrowDown`,
  `GripVertical`, `GripHorizontal` were added to `Icon`).
- Engine: prosemirror-tables 1.8.5 `moveTableRow` / `moveTableColumn` (via
  `@tiptap/pm/tables`). They read the table from the selection and replace the
  whole table in one transaction, so one move is one undo step. They select the
  moved row/column afterwards, so repeated moves work.
- Rules (`canMoveRow`, `canMoveColumn`, one place for menu and drag):
  disabled at the table edge; with a header row, row 0 never moves and nothing
  moves into index 0; disabled with merged cells (the library's helpers do not
  handle spans); row moves need a caret or one-row selection, column moves a
  caret or one-column selection.
- `moveTableLine(editor, kind, from, to, cellPos?)`: `cellPos` points the
  selection into a table the caret is not in (drag handles). The chainable
  state only re-reads the selection when `state.tr` is read; see the code.

## Handles (`components/organisms/NoteTableHandles.tsx`)

- Desktop fine pointer only. Only the grips of the hovered cell's row and
  column show, not all at once (one document `pointermove` listener; the
  last hovered cell stays while the pointer is over a grip or a dragged grip).
- Row grips straddle the table's left edge (`GripVertical`), column grips
  straddle the top edge (`GripHorizontal`). Straddling, not in the gutter,
  because the block drag handle (#335) already owns the gutter beside row 0.
  The header row has no grip. Hidden for a single row/column and for merged
  cells. Columns scrolled out of a wide table's wrapper get no grip.
- Own pointer-capture drag, not HTML5 drag and drop: the target row/column
  follows the pointer, a `stroke-secondary-active` line shows the drop edge,
  an invalid target (into the header) shows no line and drops nothing. Escape
  cancels. Drop calls `moveTableLine`.
- Geometry (position, line size) is runtime-measured and passed as CSS custom
  properties (`--grip-x`, `--line-y`, ...), same exception as
  `EditingBarMenu`'s `measure`. Everything else is Tailwind and semantic tokens
  (`bg-surface-highlight-white`, `border-stroke-lines`, `rounded-control-inner`).
- Keyboard and touch: no grip focus; use the move commands (Alt+F10 menu,
  mobile bar). Grips have `aria-label`s (`components.noteTable.rowHandleLabel`,
  `columnHandleLabel`).

## Table button under the EditingBar (`TableMenu.tsx`)

The bar is in flow above the editor (z-10). When the table is the first
block, the spot above the table sat under the bar. `triggerOffset` (floating-ui
offset function) checks whether the default spot (16px above, was 8, to leave
room for the column grips) intersects `[data-editing-bar]`; if so the button
goes below the table, or just under the bar when the table's end is off
screen. Raising z-index was not enough: they would still overlap.

## Flagged gaps

- Icons are lucide glyphs added to `Icon`; the `icon--all-icons` baseline
  changes accordingly (regenerated by `visual-update`).
- No click-to-select-row on a grip; no keyboard drag.
- Merged-cell tables cannot be reordered (library limit).
- Stories: `NoteTableHandles.stories.tsx` (`HandlesVisible`,
  `FirstBlockUnderBar`; hover is simulated with a `pointermove`).
- Tests: `tests/notes-table-reorder.test.ts`.
