# NoteTableHandles
Claude-designed on request (#387), no Figma step · Code: `components/organisms/NoteTableHandles.tsx`, move logic in `lib/notes/table-commands.ts`, Table-button placement in `components/organisms/TableMenu.tsx`

## Anatomy
Row and column reordering for notes tables. Built from existing components and semantic tokens (`bg-surface-highlight-white`, `border-stroke-lines`, `rounded-control-inner`, drop line `stroke-secondary-active`). Table menu background and design: `design/notes/NoteEditor.md` (#330).

- Fine pointer: only the grips of the hovered cell's row and column show, not all at once (one document `pointermove` listener; the last hovered cell stays while the pointer is over a grip or a dragged grip).
- Row grips (`GripVertical`) straddle the table's left edge, column grips (`GripHorizontal`) the top edge. The header row has no grip. Hidden for a single row/column and for tables with merged cells. Columns scrolled out of a wide table's wrapper get no grip.
- Four move commands (`moveRowUp/Down`, `moveColumnLeft/Right`, icons `Arrow*`) are in `TABLE_COMMANDS`, so they appear in `TableMenu` and the mobile table-actions bar without more wiring.

## Deliberate decisions
- Grips straddle the edge instead of sitting in the gutter, because the block drag handle (#335) already owns the gutter beside row 0. (#387)
- Own pointer-capture drag, not HTML5 drag and drop: the target row/column follows the pointer, a line shows the drop edge, an invalid target (into the header) shows no line and drops nothing, Escape cancels. Drop calls `moveTableLine`. (#387)
- Engine is prosemirror-tables 1.8.5 `moveTableRow` / `moveTableColumn` (via `@tiptap/pm/tables`): they replace the whole table in one transaction (one undo step) and select the moved line, so repeated moves work. (#387)
- Rules live in `canMoveRow` / `canMoveColumn`, one place for menu and drag: disabled at the table edge; with a header row, row 0 never moves and nothing moves into index 0; disabled with merged cells (the helpers do not handle spans); row moves need a caret or one-row selection, column moves a caret or one-column selection. (#387)
- `moveTableLine(editor, kind, from, to, cellPos?)`: `cellPos` points the selection into a table the caret is not in (drag handles). The chainable state only re-reads the selection when `state.tr` is read; see the code. (#387)
- `TableMenu.triggerOffset` (floating-ui offset function) moves the "Table" button when the default spot (16px above, raised from 8 to leave room for column grips) would sit under the in-flow `[data-editing-bar]` (table is the first block): below the table, or just under the bar when the table's end is off screen. Raising z-index was not enough, they still overlapped. (#387)

## Token gaps and flags
- Geometry (position, line size) is measured at runtime and passed as CSS custom properties (`--grip-x`, `--line-y`, ...), the same exception as `EditingBarMenu`'s `measure`. Everything else is Tailwind and semantic tokens.
- Icons (`ArrowUp/Down/Left/Right`, `GripVertical`, `GripHorizontal`) were added to `Icon`, so the `basis--fundament--icon--all-icons` baseline changes (regenerated by `visual-update`).

## Gotchas
- Keyboard and touch: no grip focus and no keyboard drag; use the move commands (Alt+F10 table menu, mobile bar). Grips carry `aria-label`s (`components.noteTable.rowHandleLabel`, `columnHandleLabel`). No click-to-select-row on a grip.
- Merged-cell tables cannot be reordered (library limit).
- Stories `HandlesVisible` and `FirstBlockUnderBar` simulate hover with a `pointermove`. Tests: `tests/notes-table-reorder.test.ts`.
- Touch (primary pointer not fine, #449): no hover, so the grips follow the editor selection (`selectedCell`, synced on every transaction): they show for the row and column of the cell holding the caret or cell selection and stay while the selection stays in the table. The grip's hit area grows to 46px under `(pointer: coarse)` via an `::after` (`rowHitClass`/`columnHitClass`); the visible grip stays small. Root cause was the `finePointer` gate that rendered nothing on touch.
