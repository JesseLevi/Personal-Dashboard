# /recepten page (`page.tsx` + `ReceptenBoard.tsx`)
Figma: page-level composition, no leaf component. Nodes `3761:5537` ("Pages/Recepten/Breakpoints"), `Main/Desktop` `3672:1577` > `Header` `3672:1580` + `Carousel` instance `3672:1588`. Header/BoardView/CardContainer/Carousel ids live in their own notes. · Code: `app/(app)/recepten/page.tsx` (Server Component: fetch, sweep, presign, translations), `app/(app)/recepten/ReceptenBoard.tsx` (`"use client"`: `renderItem`, navigation, panels)

## Anatomy
Composes `BoardView` with `renderItem` -> `CardContentRecipe` / `CardContentRecipeSkeleton` / `CardContentRecipeFailed` by `import_status`. Same page-level precedent as `TeDoenBoard` (not in `figma-map.json`). `ReceptenBoard` also owns `PageHeader` and renders `CategoryPanel`, `RecipePanel`, `AddRecipeMenu` and `LinkImportPanel`.

## Deliberate decisions
- Server/client split: `renderItem` is a function prop and cannot cross the boundary, so `page.tsx` passes only plain `CategoryWithRecipes[]` and strings (`title`, `addCategoryLabel`, `ingredientsLabel`, `thumbnailUrls`) (#124).
- `PageHeader` lives in `ReceptenBoard`, not `page.tsx` (unlike Te-Doen's Header/Board split): the header "Categorie" button and every column's pencil (`onEditColumn`) open the same `CategoryPanel`, so one shared `panel` state needs one owner (#125).
- Column icon comes from `recipe_categories.icon` (free text, validated by `isIconName`); the fallback is `FolderClosed`, deliberately not `Croissant`. `Croissant` is a real icon for one category (Ontbijt), so it would mislead; `FolderClosed` is the Sidebar's own Recepten glyph. Counts are `items.length` in `BoardView`, never a stored column (#124).
- Figma's 4th column (`Cake-slice`, text left at the base sample "Ontbijt"/"4") is a copy-paste leftover; only the 3 seeded categories exist. Confirmed with the user as fine to leave unbuilt (#124).
- Empty-category state reuses Te-Doen's `CardContainer` `emptyState` and the generic `components.cardContainer.addItemLabel`; Figma draws no Recepten empty state (#124).
- Card click navigates with `router.push(`/recepten/${id}`)` only for `import_status === "done"`; Figma draws no prototype link, this is our composition choice (#124, #318).
- Drag and drop has full Te-Doen parity, including in-column reorder, backed by `recipes.position` (fractional, backfilled per category by `created_at`). This reversed #124's "dragDisabled", and its rejected alternative (persist only the category change, drop `toIndex`) stays rejected: cards would jump back on refresh (#155).
  - `moveRecipe` (`actions.ts`) mirrors `moveCard` but only needs an ownership check on the target `recipe_categories` row (no parent board to mismatch).
  - `ReceptenBoard` uses the `localCategories` / `pendingMoves` (a count) / `moveQueue` / per-move snapshot revert of `TeDoenBoard`'s `handleMove`; `lib/boards/optimistic.ts` `applyItemMove<TItem, TKey, TColumn>` is the shared generic, `applyCardMove` wraps it.
  - `createRecipe` appends via `lastRecipePosition`; `updateRecipe` re-positions to the end only when `categoryId` differs from the stored one (#155).
- Search/filter is a stated scope boundary (textual search is Phase 7, pg_trgm), not a design gap (#124).
- Import (#318): the Plus button gets a `relative` wrapper and an `addMenu` slot (`BoardView.renderAddMenu`) for `AddRecipeMenu`. The board polls `router.refresh()` every 2.5 s only while a card is importing and the tab is visible (`useImportPolling`, `lib/recipes/import/polling.ts`); `sweepStuckImports` runs in `page.tsx` on each load so stuck rows show as failed, not a skeleton. Failed-card retry/delete run through `runFailedCardAction` (busy state, error line, `router.refresh()`).
- Card thumbnails: `page.tsx` presigns (#391); `imageFallbackUrl` is the route URL, set only when a presigned URL and a `thumbnail_path` both exist. Details in `CardContentRecipe.md`.
- Admin-only "Ingrediënten" header button (ADR-0020 §6, Claude-designed on request): `page.tsx` passes `ingredientsLabel` only when `isAdmin()`. Filled `Button` + `LibraryBig` icon (added to the Icon atom); mobile icon-only 40x40 with `aria-label`, desktop (`md:`) icon + label, wrapper gaps `gap-inline-sm md:gap-inline-xl` as Notities' sort button. Order: Ingrediënten, then + Categorie (primary stays rightmost) (#321).
- Offered recipes (ADR-0036, #467): `page.tsx` reads `pendingRecipeShares()` and passes `offers` (empty when there is no category, because accepting copies into the first category). `ReceptenBoard` renders them as `SharedRecipeOffer` through `BoardView.renderColumnTop` on the first column, so the offer sits above the normal cards. Accept/decline go through `acceptRecipeOffer`/`declineRecipeOffer` in `actions.ts`, then `router.refresh()`; failures show as an `offerError` line (`sharing.errors.*`) above the board. A missing sender first name falls back to `components.memberSearchPanel.unnamedLabel`.

## Gotchas
- `durationMinutes` (`"{minutes} min"`) is identical in both catalogs. Column names are `recipe_categories.name` data, never translation strings. `addLabel`/`editLabel`/`addItemLabel` are reused from `components.cardContainer.*`.
- Drag-persist failure surfaces as an inline `moveError` line (`recipes.errors.*`); no toast component exists. Create/update/delete errors show inside the panels.
- The `updateRecipe` category comparison is load-bearing: `RecipePanel` sends `categoryId` on every save, so re-positioning whenever it is merely present would drop a recipe to the bottom on each title edit, undoing a drag (#155).
- `RecipePanel` `edit` mode has no trigger on this board (cards draw no pencil); edit happens from the detail page. No new RLS needed: `supabase/tests/rls-recipes.sql` already covers every `recipes` column including `position`.
