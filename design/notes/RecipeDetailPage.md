## Structure

- **Shell reuse:** `AppShellNav` already supplies the persistent Sidebar / mobile panel button and `main`'s `pt-4 pb-20 pl-4 md:pt-20 md:pb-20 md:pl-32`; this page adds only the right half via `pr-page-right-equal` on its root wrapper (`gap-page-stack`).
- **No `PageHeader`:** Figma's header row (back arrow left, buttons right) has no `<h1>` slot; the title renders centred below the hero. Plain `flex justify-between` row.
- **Server/client:** `page.tsx` keys `RecipeDetailPage` on `recipe.id` (local state resets deterministically). `RecipeDetailPage` is a full `"use client"` component (edit/delete/router need page-level client state); ADR-0002/0003 still hold: `recipe`/`categories` arrive as props, scaling runs client-side over already-fetched data, no client-side Supabase call.
- **`notFound()`:** `getRecipeWithIngredientsAndSteps` returns `null` for missing / not-this-user's (RLS) / signed-out alike; `page.tsx` calls `notFound()` for all three.
- **No Ladle story:** composes only storied pieces (`Card`, `CardContentIngredient`, `CardContentStep`, `Button`, `Dropdown`, `PortionStepper`), no extracted reusable unit; same precedent as `ReceptenBoard.tsx`.
- **No category tags:** no category `Tag` row in any fetched node, V1 or V2, though `recipe_categories` exists: a Figma-recorded scope boundary, not a gap.

## Header, delete, overflow

- **"Voeg toe aan mand"** is `AnimatedAddToBasketButton` (labelled, node `4051:12888`; mechanism in `design/notes/AnimatedAddToBasketButton.md`). `handleSendToList` sends `{ recipeId, targetPortions: portions }` to `sendRecipeToShoppingList` (`app/(app)/winkelmand/actions.ts`): the session `portions` state, never `recipe.servings`. A dedicated `useTransition` (`sendPending`) disables it in flight, separate from `handleDelete`'s `isPending` (different branches). The action loads the recipe server-side (ownership via the query's RLS + `user_id` filter, never service_role), scales+merges via pure `lib/shopping/send-to-list.ts` (`buildShoppingListLines`, reusing `scaleIngredientRows`), and inserts with `recipe_id` set, appended after existing items. Whole-recipe send only; no success feedback (`docs/open-questions.md#winkelmand-send-no-success-feedback`; the animation plays unconditionally, a known accepted cost: a failed insert was once hidden behind "Toegevoegd").
- **Ingredient rows** use `swipeAction="cart"` (`design/notes/CardContentIngredient.md`): the revealed icon-only `AnimatedAddToBasketButton` calls `handleAddIngredientToCart(ingredientId)` -> `addIngredientToShoppingList` (fire-and-forget, no success/failure UI), scaled to session `portions`. The action reuses the ownership-checked recipe loader and `mergeSingleIngredientLine` in `lib/shopping/send-to-list.ts`; unlike the bulk send it **merges into an existing row** (same name + unit) instead of always inserting. Accessible label is per item: `addIngredientToBasketLabel` ("Voeg {name} toe aan mand") interpolates the ingredient name; `components.cardContentIngredient.addToCartLabel` stays the generic string for stories.
- **Mobile Ellipsis overflow menu** (`3778:5434`, icon-only, no annotation, no panel in Figma): built as `TeDoenHeader.tsx`'s pattern: local `overflowOpen`, `aria-expanded`, `Atom/Dropdown` labelless panel with "Bewerken" (`white`) / "Verwijderen" (`destructive`), positioned through the shared `lib/dom/use-popover-position.ts` (`anchor="right"`, `prefer="below"`; `docs/incidents.md`, 2026-08-18). Undesigned, built least-inventively.
- **Delete confirmation:** no confirm dialog exists in Figma. Two-step per `CardDetailPanel`'s #94 precedent ("Weet je het zeker?" + Annuleren/Ja-verwijderen, no `window.confirm`), `flex-wrap` row, one `deleteConfirming` state with two triggers (desktop button, overflow row). `handleDelete` calls `deleteRecipe`, on success `router.push("/recepten")`; errors render inline via `recipes.errors.*`.
- **"Bewerken"** opens `app/(app)/recepten/RecipePanel.tsx` in `{ mode: "edit", recipe }`; `categories` come from `getRecipeCategoriesWithRecipes()` (same as `ReceptenBoard`). **Known redundancy:** the panel's own edit-mode footer still has "Verwijderen", a second delete affordance; both call `deleteRecipe`, and this page's `onDeleteRecipe` wraps it with the `router.push("/recepten")` redirect (not `router.refresh()`, whose route no longer exists). `editTarget`'s `recipe` stays the **unscaled** stored one.

## Ingredient and step cards

- **Groups:** one `Card` per `group_label`, first-seen order (by `position`); a recurring non-contiguous label merges into its first bucket. **`group_label`-less ingredients get the default title** `group.groupLabel ?? t("ingredientsDefaultTitle")` ("Ingrediënten"/"Ingredients") by user instruction (#166, overruling the earlier "no heading" literal read); still one shared bucket for all `null`-label rows.
- **Divider** is drawn between rows only: `divider={index < group.ingredients.length - 1}` (Figma removed the border from `Card-content/Ingredient` in V2; ownership in `design/notes/CardContentIngredient.md`). The underline is an unrounded sibling div there (a lone `border-bottom` on `rounded-3xl` curves at the corners).
- **Step ingredient tags** (`withIngredientTags`): each step's `ingredientIds` (`RecipeStepWithIngredients`, ordered by the link's `position`) are looked up in `recipe.ingredients` via a `Map` built once per render; an unmatched id is silently dropped; an empty list renders `withIngredientTags={false}`. Figma draws one combined Tag per ingredient, **quantity + short unit + name** ("2 tbs Chia Seeds", "375 ml Non Dairy Milk"), `Color=Grey` = `Tag`'s `neutral` variant (no gap). Order is the join's `position`, not re-sorted or deduplicated. Step Tags use `recipes.unitsShort` + `formatQuantityFraction`; the ingredient-card Tag keeps the long `recipes.units` label.
- **Settings slot:** `Card`'s `settings?: ReactNode` (Figma `Settings` boolean, instances `3997:25493`/`3998:10755`, icon-only `Settings2` Button, annotated to launch the PasAan panel) renders on the **first ingredient group's Card only** (`groupIndex === 0`): Personen/Eenheid are recipe-wide, so repeating the trigger per group would duplicate one control. A reasoned extension of the single sampled instance, not a literal read. `Card.tsx` renders its title row even without a `title` for this (`design/notes/Card.md`).

## Portions, scaling, units (display-only)

- `PortionStepper` is the page's `portions` state (initial `recipes.servings`), floored at its own `min` (default 1; clamp lives in the atom, `design/notes/PortionStepper.md`). **Display-only: no server action, no `recipes.servings` write**; resets on navigation (the shopping list resolves at send time, `Architecture.md` §4.2).
- `lib/recipes/scaling.ts` (`scaleIngredientRow`/`scaleIngredientRows`) maps `scaleQuantity` over `recipe.ingredients` from `servings` to `portions`, then (optional `unitSystem`) `convertToUnitSystem`, then (optional `masses`/`getMasses`) `convertToKitchenUnit`, all in **one pass**; `displayIngredients` is the one list feeding both the ingredient `Card`s and the per-step Tags. Never throws in render: `InvalidPortionCountError` falls back to the row's unscaled quantity (`servings > 0` is DB-checked, the stepper floors at 1). Omitting `masses` reproduces plain `convertToUnitSystem` behaviour exactly. Tests: `tests/recipes-scaling.test.ts` (wiring), `tests/recipes-units.test.ts` (arithmetic), `tests/recipes-kitchen-units.test.ts`.
- **`convertToUnitSystem(quantity, unit, system)` is membership-based, not normalising** (`lib/recipes/units.ts`): it converts a unit only if it is *foreign* to `system`. Metric membership: gram, kilogram, milliliter, deciliter, liter, theelepel, eetlepel. US: ounce, pound, cup, teaspoon, tablespoon, fluid_ounce. A foreign unit lands on one **flagship unit per magnitude** (metric: gram/milliliter; US: ounce/cup). The flagship choice is a build decision, not Figma (the Eenheid annotation names only "Amerikaans"/"Metrisch"); best-fit-per-quantity selection is out of scope (flagged in `units.ts`). Never normalise unconditionally (the "2 eetlepel olijfolie" -> "30 milliliter" regression); `tests/recipes-units.test.ts` locks same-system passthrough. `count` units (stuk, snufje, scoop, naar_smaak) render as-is in either system. Foreign conversions round to 2 decimals (`roundQuantity`). **Default `metric`**: Dutch-metric recipes render exactly as entered on first load.
- **Kitchen units** (`lib/recipes/kitchen-units.ts`, pure, composes `convert()`/`convertToUnitSystem` with an already-resolved per-ingredient mass, ADR-0011 §3): `convertToKitchenUnit` intercepts exactly two flagship landings: mass -> `ounce` under "us" becomes `cup` (stepping to tablespoon/teaspoon below 1/4 cup and 1 tablespoon, exclusive) when `masses.cup` resolves; a foreign volume unit (cup/teaspoon/tablespoon/fluid_ounce) landing on `milliliter` under "metric" becomes `gram` when `masses[unit]` resolves. ml/dl/l/eetlepel/theelepel are never touched ("375 ml stays 375 ml"). Masses reach the client as plain data `RecipeIngredientWithNutrition.kitchenUnitMasses` (`lib/recipes/types.ts`; a resolver function can't cross the Server -> Client boundary), read by `kitchenUnitMassesFor` from the batch already fetched by `nutritionInputsForIngredients` (no second round trip), resolved by `resolveMassWithBridge` (user override -> reference -> bridge).
- **Fraction notation (`formatQuantityFraction`):** ASCII ladder (eighths/quarters/thirds/halves), 0.02 snap tolerance (+`1e-9` epsilon for IEEE noise), mass-magnitude quantities stay decimal (`magnitudeOf`). Sibling of `formatQuantity`, which stays for places without a UnitCode (`NutritionalDataRow` figures).
- **`recipes.unitsShort`** (17 keys, identical to `recipes.units`, both catalogs): abbreviated labels ("g", "ml", "tbs", "el", "tl", "fl oz"); the four count units without a real abbreviation reuse their lowercase long word. Used only at the per-step Tag.

## NutritionalData row (`NutritionalDataRow.tsx`)

Seven `Button/Default` pills (mobile `3997:15948` wraps, `justify-center`; desktop `3997:15543` single row, `justify-start`): Timer/time, Flame/calories, Wheat/carbs, BicepsFlexed/protein, Droplet/fat, LeafyGreen/fibre ("Vezels", node `4025:11826`), User/servings. Icons verified path-for-path (`design/notes/Icon.md`).

- **Time** = `recipes.time_minutes` (nullable). **Macros** come from `computeRecipeNutritionPerPerson`, called once per render on the **original unscaled quantities and `recipe.servings`**, deliberately NOT `displayIngredients`/`portions`/`unitSystem`: per-person nutrition is portion-invariant, and recomputing it from display state would launder a display-only unit conversion into a nutrition input (`lib/recipes/nutrition.ts` separates conversion from nutrition math).
- **Unknown = "?"** (annotation on `3997:15950`, covers all buttons): `formatValue` renders `t("nutrition.unknownValue")` for any `null`, never a fabricated `0`. Macros are display-rounded by `formatMacro` (`Math.round` before `formatQuantity`; stored/summed values stay full precision; `null` short-circuits to "?"). Real data (ADR-0013): NEVO-online 2025/9.0 per-100g for 2,275 of 2,328 `reference.ingredients` rows; the 53 `per_100ml` rows (infant formula) are deliberately read as unknown. Household-unit masses come from `reference.ingredient_unit_masses` (USDA seed + bridge); a unit with no resolvable mass still yields `?`. The four+ macro dropdowns carry the NEVO attribution line (ADR-0013 §2).
- **Five buttons open a dropdown** naming the full word (annotations `3997:15949`-`3997:15953`, `4025:11826`): `Atom/Dropdown` labelless bordered-panel with one line of text, click-outside closes, one shared `openKey`/ref per row (one popover at a time). Content is Figma-specified, exact visual (width/padding/position) is not.
- **Servings button** (`3997:16065`/`3997:25590`) has no annotation: rendered **`disabled`** (the same "real but non-functional" precedent the header button once had); no handler invented. It shows the session `portions`, never `?`.
