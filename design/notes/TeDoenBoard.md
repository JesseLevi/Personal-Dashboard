## Anatomy
`PageHeader` + `BoardView` + `CardContentTicket` + `Tag`, composed as Figma nests them. Page-level composition, not an atomic-design leaf, so none of these files are in `design/figma-map.json` (same precedent as `AppShellNav`).
- Server/client split: `BoardView`'s `renderItem` is a function prop and cannot cross the Server->Client boundary, so the Server Components fetch plain serialisable `BoardWithColumns` and `TeDoenBoard` (`"use client"`) owns `renderItem` and everything using `useTranslations` / `useFormatter`. `TeDoenBoard` is the only file importing `./actions`.
- Ticket card = `CardContentTicket` with `Tag`s ordered priority, size, due date. `CardDetailPanel` opens from `onAddItem` / `onItemClick` via one `{open, target}` state (independent, so the close transition keeps its content).

## Deliberate decisions
- Active board comes from the URL: `/te-doen/[boardId]`; `/te-doen` and any id that does not resolve to one of the user's boards (deleted, foreign, malformed) fall back to the favourite (else first board) instead of a 404. If the user has no boards at all, a translated empty state renders (`components.pageHeader.todo.emptyBoard{Title,Body}`). Board switching and sorting both preserve the other param. (#95)
- Priority maps 1:1 onto `Tag` variants. The DB type is plain `string`, so `isPriority` guards it and falls back to `medium` (the DB default). Labels come from `boards.priority.{low,medium,urgent}`, not Figma's sampled Tag text ("Medium", "Mid", "300 gr" are stale placeholders, `Tag.md`). (#93, #97)
- Size is data, not a translated label: `Tag neutral` with `size.toUpperCase()`, omitted when null (ADR-0025). Due date uses `useFormatter().dateTime` (2-digit/2-digit/numeric, active locale), omitted when null. (#93)
- Column icon is DB free text, so `isIconName` (`Icon.tsx`) guards it and falls back to `CardContainer`'s `"Croissant"`; the same free-text-vs-union gap exists for recipe categories (ADR-0027). (#93)
- Sort is a view, not a mutation: `?sort=createdAt|priority|size|alphabetical` reorders each column's fetched cards in memory in `board-data.ts` (`lib/boards/sort.ts`), `position` is never written. No param = manual order, deliberately not "Aanmaakdatum" even though the Figma sample shows it selected; nothing is pressed until the user picks one (2026-07-25). An invalid `?sort=` means no sort. Priority order is `urgent > medium > low` (the schema has no `mid`). (#95)
- Dragging is disabled while a sort is active: `TeDoenPageBody` passes `dragDisabled={sort !== null}` through `TeDoenBoard` to `BoardView`. Rejected: resetting sort on drag start (navigation mid-gesture races the drag) and writing a drop against the sorted view (the `position` would sit between unrelated manual-order neighbours, a result nobody chose). Cards stay clickable; clearing the sort restores drag. Do not bypass it when touching `onMove`. `NotitiesBoard` follows the same precedent. (#95)
- Board switcher is a labelless `Dropdown` of `Button` rows (filled = active, white = others) plus `Button outline icon="Plus"` "Toevoegen" opening `BoardPanel` in create mode. The favourite star is `Star` disabled when already favourite and `StarPlus` otherwise (`toggleBoardFavorite` then `router.refresh()`): the UI must never offer un-favouriting (exactly-one-favourite constraint, ADR-0026). (#95)
- Board delete is not built, on purpose: Figma's AddBoard footer shows a Verwijderen button, but the kanban migration says reassigning the favourite after a delete belongs to the board-delete ticket, and building it here would invent that behaviour. Board rename has no trigger either: `BoardPanel` supports `{mode: "edit"}` but no Figma header frame draws a pencil, so none was invented. Add both once Figma draws them. (#95)
- `createBoard` also inserts `lib/boards/defaults.ts`'s `DEFAULT_BOARD_COLUMNS` (Ideeen/Klaar/Bezig/Afgerond) because the `seed_default_board()` trigger only fires for a new account's first board. The column insert is best-effort (logged, not rolled back): the board already exists. (#95)
- Both header dropdowns use `lib/dom/use-popover-position.ts` (board switcher `anchor="left"`, sort `anchor="right"`, both `prefer="below"`), which clamps into the viewport. Figma's "align right, fall back to left" is still not built (a product call); the hook only closes the clip-off-screen failure. (2026-08-18, `docs/incidents.md`)
- Drag persistence: `handleMove` applies `applyCardMove` (`lib/boards/optimistic.ts`, framework-free, same remove-then-insert semantics as `moveCard`) to a local copy of the board (`localBoard`), then calls `moveCard`. Two optimistic layers exist: `BoardView`'s internal gesture state and this local copy above it (without it, any re-render made `BoardView` re-sync from the unchanged prop and cancel the dropped move). On failure the pre-move snapshot is restored and a translated `boards.errors.*` message renders inline (no toast component exists). (#96)
- `moveCard` calls are serialised through a `moveQueue` promise chain so a second drop computes its siblings against persisted state; `pendingMoves` is a count, not a boolean, and the `localBoard`-from-`board` sync effect is skipped while it is non-zero. Known residual: if the first of two queued moves fails, its rollback can briefly discard the second's optimistic result until that one resolves; the board always converges on server truth. (#96)
- A successful move does NOT call `router.refresh()`; every other mutation (create/update/delete/rename) does. The refresh tied the drop's landing to a network+RSC round trip (visible multi-second stall on slow Supabase), while the optimistic apply already is the landed state and `moveCard` re-reads live sibling positions server-side. Ladle showed the drop settling about 246ms after mouseup (dnd-kit's own 250ms animation), so the cause was here, not in `BoardView`. Unverified against a real authenticated route. (#114)
- Column edit/create/delete: one shared `CategoryPanel` behind `TeDoenColumnPanelProvider` (header "+ Categorie" creates, each column pencil edits name + icon and deletes). The provider holds the only open/target state and is the only "use server" import site for these actions, with thin adapters (`categoryId` -> `columnId`, `boardId` injected). `renameColumn` takes an optional `icon`; `deleteColumn` cascades cards. Icon choices: `column-icons.ts` (four default-column icons first).
- Board switch motion (#413): `TeDoenBoardSwitchProvider` (in `TeDoenPageBody`) lets the header's `goToBoard` call `switchTo(id, href)`. The columns play `animate-blur-out` (`BoardView.columnMotion="out"`, staggered left to right), then after `blurOutTotalMs` it calls `router.push`; `router.prefetch` fires on click so loading overlaps the exit. The old board stays hidden (fill `both`) until the route swaps, then the existing skeleton shows. The new board plays `animate-blur-in` only when a module-level flag says it arrived via a switch (`wantsBoardEnter`), so first loads, reloads, sort changes and refreshes never animate. The `columnMotion` prop is dropped after `blurInTotalMs`: a lingering fill would leave `filter: blur(0)` on the columns and break drag overlays.
- Done styling: cards in the last column (last in position order, not by name) are muted via `BoardView`'s `isItemMuted`.
- Arriving from login (the `atlas:enter-from-login` sessionStorage mark, `lib/ui/login-enter.ts`) blurs the page in: `EnterFromLogin` wraps the header (index 0) and the board (index 1) in `TeDoenPageBody`, each with `animate-blur-in` and a stagger. Ordinary navigation, reloads and stale marks (older than 10s) never animate. No flash: the first render matches the server HTML, and `useLayoutEffect` reads the mark and sets the class before the first paint. The class is removed after the animation, because its fill keeps `filter`, which would make the wrapper a containing block for the fixed side panels. Wrappers sit around the header and board, never around the panels' own roots.

## Gotchas
- `applyCardMove` never computes `position`; only `nextPosition` (`lib/boards/positioning.ts`) on the server does. Repeated bisecting between the same neighbours eventually exhausts float precision and surfaces as the `"generic"` error; there is no re-spacing pass (pre-existing gap).
- Not verified on the dev machine (no Docker/Supabase): drag surviving a hard refresh, keyboard-driven move persisting, the rollback message against a real failed request, and queue behaviour under real latency.
