   - **Recipe reordering has no design answer at all.** #124's ticket body told it to persist drags to `recipes.position`, but #119's schema deliberately has no such column ("recipes are not reordered within a category in this phase's design"), so `/recepten` ships `dragDisabled`. If drag-to-recategorise is wanted it needs a ticket *and* a schema decision — `design/notes/ReceptenBoard.md` records the deliberately rejected half-measure.
   - **`recipes.thumbnail_path` is not read anywhere yet.** Every recipe card renders a `bg-surface-muted` placeholder because #121's bucket doesn't exist. Figma draws no "no photo" state: `docs/open-questions.md#recipe-card-no-photo-placeholder`.
   - **#122's ingredient/step writes are replace-not-diff and NOT transactional.** supabase-js only reaches a real Postgres transaction through an RPC and no migration was in #122's scope, so `replaceRecipeIngredients`/`replaceRecipeSteps` do delete-then-insert as two sequential statements. `createRecipe` compensates by deleting the just-created recipe; **`updateRecipe` does not** — a delete that succeeds followed by a failing insert leaves an existing recipe with no ingredients or steps. **Decide on an RPC-backed transaction before #126 wires a real edit form to it.**
   - **#122's library search is `ilike`, not `pg_trgm`.** `Architecture.md` §103 scopes pg_trgm to Phase 7 columns and no migration enables the extension, so `searchIngredientLibrary` uses escaped case-insensitive substring matching — correct for the hand-curated seed, not similarity-ranked. Swapping it is a small follow-up once a migration adds extension + index.
   - **`PortionStepper` does not clamp** — decrementing at 1 emits 0, deliberately, because portion state is caller-owned: **#128 owns the minimum.** Its decrement button renders lucide's `Minus` while both Figma nodes draw `Icon/Plus` twice (`docs/open-questions.md#portion-stepper-figma-draws-plus-twice`).
   - **Nutrition columns exist but stay empty in Phase 4.** `NULL` means unknown and must never be coerced to `0`; the seed carries no nutrition figures at all. NEVO data must never enter the repo (its licence forbids reshaping); USDA FoodData Central is the backbone, CIQUAL an allowed supplement with source+version attribution, and sources are never mixed within one ingredient row.
   - **The `unit` enum is `public.recipe_unit` and it lives in #130's migration.** Anything adding a unit column reuses this type; never declare a second one. `tests/recipes-units-enum-sync.test.ts` compares its values to `UNIT_CODES` for real and fails on any drift.
   - **`reference` is a real schema** (two-layer ingredient library — see `ADR-0011`, which supersedes the earlier "no library" reading of §4.2) **and `scripts/check-rls-coverage.sh` has a second pass for it**: no `user_id`, select-only client grants, RLS on. `supabase/config.toml` exposes it and `db:types` runs `--schema public,reference`. If you add a table there, those three still apply. `recipe_ingredients.name` stays denormalised and always filled — the FK enriches, it is never required to render.
