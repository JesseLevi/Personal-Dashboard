- **#263 (merged, PR #264)**: the first real feedback round on `/notities`, and all three items had a root cause worth carrying. (1) **A bare `hidden` on a `Button` does nothing.** `Button.tsx`'s cva *base* class carries `inline-flex`, cva never merges classes, and in the compiled sheet `.inline-flex` is emitted after `.hidden` (measured offsets 13540 vs 13496) — so the class loses on declaration order. `md:hidden` works (media variants come later), which is why only mobile showed two sort buttons and desktop looked fine. (2) **`position: fixed` anchors to the *layout* viewport**, but iOS's keyboard only shrinks the *visual* one, so the EditingBar sat behind the keyboard. A `visualViewport`-derived inset is applied as a CSS custom property, keeping the breakpoint split in Tailwind (`md:translate-y-0`) instead of a JS media check. (3) **"heading/list/quote/code do nothing" was not an extension problem at all** — every extension was installed and correctly wired. Tailwind's preflight strips heading sizes and list markers, and the editor root applies a flat `text-base font-semibold`, so all four block types rendered identical to a paragraph. Fixed with a token-bound `.tiptap` block in `app/globals.css`. Worth generalising: **a command whose only evidence is the rendered document will read as broken until something on screen distinguishes it.** → `docs/open-questions.md#notes-prose-typography-not-designed`

## Traps that have already cost a session

- **Committing a migration does not apply it.** `deploy.yml` is `workflow_dispatch`-only, so a push to `main` deploys code and migrates nothing. Check `supabase_migrations.schema_migrations` on the hosted project *before* debugging a data-shaped bug.
- **`deploy.yml` has no migrate-only mode.** Its `deploy` job hangs off `needs: migrate`, so applying a migration to hosted **also promotes `main` to production**, in one action. Confirm with the user before dispatching it; that is a user decision (ADR-0012), not a routine step.
- **A migration applied by hand or via the Supabase MCP server gets that route's own timestamp as its version**, not the repo filename, and `supabase db push` then refuses. Correct the version row by hand every time a migration reaches hosted outside `deploy.yml`.
- **Never batch a migration across parallel agents** — that raced two writers into 250 duplicate `reference.ingredients` rows on #161. One sequential call.
- **Two `db` jobs cannot run concurrently** — the runner starts a real Supabase stack on fixed ports, so the second dies on `failed to bind host port for 0.0.0.0:54324` (measured 2026-08-13, two Phase 6 PRs open). Reads like a broken migration; the log shows all migrations applying, then the container failing. Wait, then `gh run rerun <id> --failed`.
- **Visual flake: isolation is not a control — run the FULL suite twice.** Identical code has given fail-then-pass across consecutive full runs, and a story that failed 3/3 *in isolation* passed in a full run — story count, ordering and parallelism all change the rasterization. Never bisect a visual failure. Never let two runs overlap. **Part of this was the gate itself** (#203): `maxDiffPixels` was 0, and Skia's rounded-corner antialiasing is not bit-reproducible between runs — measured on `main`, the same three stories gave 0, then 1/4/5, then 0 differing pixels, always ±1 in one channel. It now sits at 16, which still leaves ~450× headroom under a real token regression. `threshold` stays 0 and must never be widened: that is the knob that catches grey-on-grey. **The flake can exceed 16**: #233's first full run failed `card-detail-panel--edit-item` at **22 pixels** on a branch that touches no `components/` file, and the next full run was 110/110 with nothing regenerated — so a lone failure above the threshold still is not evidence of a regression. Re-run the full suite before believing it.
- **A recorded blocker carries the environment it was measured in — check that before treating it as a wall.** #190 sat parked as "blocked on the `reference` schema" through several sessions. The observation was real but *hosted-only*; CI's local stack was never affected, and the gate turned out to be ~13 lines away. Before planning around a documented constraint, ask which environment produced it.
- **Verify a ticket's Figma links resolve before planning against them.** Two nodes cited by #166 no longer exist in the file.
- **An optimistic success animation can hide a fully broken write path.** `AnimatedAddToBasketButton` plays "Toegevoegd" regardless of the `ActionResult`, which masked a failing insert for an entire ticket. → `docs/open-questions.md#winkelmand-send-no-success-feedback`
- **iOS only reads the manifest/`appleWebApp` metadata (#172) when an icon is added to the home screen.** An icon added before this shipped keeps opening in tabbed Safari forever — the user must delete and re-add it after this deploys. → `design/notes/AppShell.md`

This is the same shape as #238's finding that no story renders a `:hover` state: the suite passes because the thing was never drawn, not because it is right.

- **`getClaims()` verifies the JWT locally, so revocation is not immediate** (#168, deliberate). A session revoked server-side — sign-out-everywhere, a banned or deleted account — stays accepted until the access token expires, where `getUser()` caught it on the next call. This is inherent to Supabase's JWT-signing-keys model, which the ticket mandates, and is the source of the latency win. If signing keys are ever switched off, supabase-js falls back to a full `getUser()` network call automatically — the cost returns, the check does not weaken.
- **Production promotion is manual** (ADR-0012): either "Promote to Production" / `vercel promote` on an existing build, or a `workflow_dispatch` run of `deploy.yml` (verified green 2026-08-07, #165), which migrates and promotes together. Either way, migrations land first.
