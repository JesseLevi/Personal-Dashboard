## Nothing below has run for real

There is no Docker on this dev machine, so **no Phase 3 database path has ever executed against a live Supabase**, and #96's acceptance was never exercised in a real browser. Close these before trusting the board in production.

- **Live Supabase, never run:** `createBoard`'s default-column seed; `/te-doen/[boardId]`'s RLS-filtered fetch; `toggleBoardFavorite`'s exactly-one-favourite behaviour; `getBoardWithColumns`'s nested PostgREST select and `moveCard`'s `board_columns!inner(board_id)` embed (both reasoned against the installed postgrest-js API only, never executed); the `service_role` GRANT migration `20260724210000_grant_service_role_kanban.sql`. **Add all of #122's `lib/recipes/queries.ts` and `app/(app)/recepten/actions.ts` to this list** — the nested category→recipes and recipe→ingredients/steps embeds, the cross-schema `reference` search, and the mass-resolution lookups are reasoned against the postgrest-js API only. CI's `db` job proves the *schema* works, not these queries.
- **`lib/database.types.ts` is hand-written** — its own header says so — **and no CI job checks it.** The `db` workflow job runs `supabase start`, `supabase test db` and the RLS coverage gate, but has no `db:types` step, so a drift between the hand-written types and the real schema would pass every gate silently. Every query written against these types (all of `lib/boards/` and now all of `lib/recipes/`) inherits that risk. Fix by adding a `pnpm db:types` + `git diff --exit-code` step to the `db` job.
- **Real device, never run: #114** — the reported desktop drop-hover bug. The fix is reasoned (Ladle measurement ruled out drag mechanics) and merged, but never watched fixing the symptom on the real `/te-doen` route. #116/#118's mobile drag, by contrast, has now been watched working on real iPhone/iPad Safari — see the bullet above.
- **Real browser, never run:** the entire #96 drag-persist acceptance — a drag surviving a hard refresh, keyboard-move persisting like mouse, rollback against a genuinely failed request, and two quick drags under real latency. Also `TeDoenHeader`'s sort and board-switcher dropdowns: they call `useRouter()`, which throws under Ladle's plain Vite runtime, and `/te-doen` needs a real Supabase session. The identical `Dropdown` code path *was* verified through the `Dropdown`/`CardDetailPanel` stories; the sort menu in situ was not.
- **`toggleBoardFavorite` is not transactional.** It clears the old favourite and sets the new one in two sequential statements — a failure between them transiently leaves zero favourites (never two; the partial unique index blocks that), self-healing on the next toggle.
- **The visual gate protects local runs only.** All 59 committed baselines are `-darwin.png` from this Mac and there are zero `-linux.png`, so CI's `visual` job is `continue-on-error: true` and cannot fail the build. Close it by generating Linux baselines inside the pinned `mcr.microsoft.com/playwright` container (a `workflow_dispatch` job whose output a human commits), then remove `continue-on-error`.
- **Two round-2 acceptance claims are still unproven.** **#109's** "no text jump on collapse" now *does* have frame-by-frame `getBoundingClientRect()` evidence (see `design/notes/Sidebar.md`'s #109 entry — resolved). **#110's** hidden scrollbar was never confirmed still scrollable by wheel/trackpad/touch/keyboard, nor tested at two viewport widths, in both sidebar states, or with a drag after horizontal scrolling (the columns are `useDroppable` bounding-rect targets, so a negatively-margined scroller can break hit-testing) — still open. **#111's** fix (clearing a residual inline `transform`) is superseded, not confirmed or retracted: the user reported the same stale-overlay symptom again after #111 shipped, so round 3 (#113) shipped a different, independently-reasoned fix (`visibility`/`transition-discrete` + `viewport-fit=cover`) on top of it — also unverified on a real device, see `docs/open-questions.md#ios-safari-fixed-viewport-unverified`.
- **`card-detail-panel--edit-item` is a flaky baseline, on top of being a useless one.** It failed, then passed unchanged on re-run, then was not rewritten by `--update-snapshots`. Same sub-perceptual antialiasing as #106's crops — one more reason to fix that suite.
- **#106 (Backlog): the two `card-detail-panel` baselines are sliver crops that cover essentially nothing.** Proven, not suspected — #100 added a visible chevron and #103 made the footer full-width in exactly those stories, and both baselines still passed byte-identical. Until #106 lands, treat the zero-tolerance suite as a *silent* gate on the app's highest-traffic panel. #106 must prove the regenerated baselines actually fail on a deliberate small change, not merely that the crop got bigger.

An RPC-backed transaction is the open follow-up; decide before #126 wires a real edit form to it.
   - **#122's library search is `ilike`, not `pg_trgm`.** The ticket asked for trigram search, but `Architecture.md` §103 scopes pg_trgm to Phase 7 columns and no migration enables the extension or indexes the ingredient name columns. `searchIngredientLibrary` uses escaped case-insensitive substring matching — correct for the hand-curated seed, not similarity-ranked. Swapping it is a small follow-up once a migration adds extension + index.
   - **#123 deviates from Figma: both portion-stepper nodes draw `Icon/Plus` on the left AND the right.** The decrement button renders `Minus` instead — deliberate, recorded at `docs/open-questions.md#portion-stepper-figma-draws-plus-twice`. Quantities round to **2 decimal places** (`+Number.EPSILON` correction) — deliberate, so scaling never emits noise like `0.3333333333333333`; see the rounding comment in that file before changing it.
   - **The `unit` enum is `public.recipe_unit` and it lives in #130's migration, not #119's.** Both `ingredient_unit_masses` tables needed the column before `recipe_ingredients` did, so creating it anywhere else would have meant two enums. `tests/recipes-units-enum-sync.test.ts` is no longer a trivially-passing tripwire — it now compares that enum's values to `UNIT_CODES` for real and fails on any drift.
